# Chapter 5: Interrupts and device drivers

## 概述

设备驱动程序是内核中管理特定设备的代码：它配置设备硬件、告诉设备执行操作、处理产生的中断、与等待设备I/O的进程交互。

## 设备基础知识

### 设备接口

大多数设备通过内存映射I/O（memory-mapped I/O）提供接口：
- 设备将其控制寄存器映射到物理地址空间
- 内核使用`load`/`store`指令读写这些寄存器
- 写寄存器触发设备执行操作
- 读寄存器获取设备状态或操作结果

### 设备驱动程序结构

设备驱动程序通常分为两部分：
1. **下半部分（bottom half）**：在中断处理程序中运行，快速完成
2. **上半部分（top half）**：在系统调用中运行，可以等待

### 中断 vs 轮询

- **中断**：设备完成操作时发送信号，CPU及时响应
  - 优点：及时响应，不浪费CPU周期
  - 缺点：中断开销
- **轮询（polling）**：CPU定期检查设备状态
  - 优点：简单，无中断开销
  - 缺点：浪费CPU周期，响应延迟

## 5.1 代码：控制台输入

### UART（通用异步收发器）

xv6使用UART硬件实现控制台：
- UART是一种硬件设备，用于与其他计算机或设备进行串行通信
- QEMU模拟16550 UART芯片
- 16550可以以高达每秒百万位的速度传输数据

### UART寄存器映射

UART寄存器通过内存映射I/O访问：
- `UART0`（0x10000000）：UART控制寄存器的基地址
- 每个寄存器8位宽
- 寄存器相对于`UART0`的偏移：

| 偏移 | 名称 | 读/写 | 用途 |
|-----|------|-------|------|
| 0 | RHR | 读 | 接收保持寄存器（已接收的字符） |
| 0 | THR | 写 | 发送保持寄存器（要发送的字符） |
| 1 | IER | 读/写 | 中断使能寄存器 |
| 2 | ISR | 读 | 中断状态寄存器 |
| 2 | FCR | 写 | FIFO控制寄存器 |
| 3 | LCR | 读/写 | 线路控制寄存器 |
| 5 | LSR | 读 | 线路状态寄存器 |

### 控制台输入处理

1. 用户在键盘上输入字符
2. UART接收字符并将其放在RHR中
3. UART触发接收中断
4. `uartintr()`（kernel/uart.c:180）从UART读取字符
5. `uartintr()`调用`consoleintr()`（kernel/console.c:74）
6. `consoleintr()`将字符放入输入缓冲区
7. 如果字符是换行符，唤醒等待输入的进程

### 输入缓冲区

```c
struct {
  struct spinlock lock;
  char buf[INPUT_BUF];
  uint r;  // 读索引
  uint w;  // 写索引
  uint e;  // 编辑索引
} cons;
```

- `cons.buf`：环形缓冲区
- `cons.r`：下一个要读取的位置
- `cons.w`：下一个要写入的位置
- `cons.e`：编辑位置（用于退格键）

### 行编辑

`consoleintr()`支持简单的行编辑：
- 普通字符：添加到缓冲区
- `^H`（退格）或`DEL`：删除前一个字符
- `^U`：删除整行
- `^D`：文件结束符

## 5.2 代码：控制台输出

### 写控制台

当进程调用`write`到文件描述符1（stdout）时：

1. `filewrite()`调用`pipewrite`或`devsw[major(dev)].write`
2. 对于控制台，`devsw[CONSOLE].write`指向`uartwrite`
3. `uartwrite()`（kernel/uart.c:93）将字符逐个发送到UART
4. 对于每个字符，等待THR为空（LSR第5位为1）
5. 将字符写入THR

### 回显（Echo）

`consoleintr()`会回显（echo）输入的字符：
- 调用`uartputc()`输出字符
- 用户可以看到他们输入的内容

## 5.3 驱动程序中的并发

### 并发问题

设备驱动程序中存在几种并发：
1. **进程与中断处理程序**：进程可能正在使用设备，同时中断处理程序处理设备完成
2. **多个进程**：多个进程可能同时尝试使用同一设备
3. **不同CPU上的中断**：不同CPU上可能同时处理设备中断

### 锁的使用

xv6使用锁保护共享数据：
- `cons.lock`：保护控制台输入缓冲区
- `uart_tx_lock`：保护UART发送

### 睡眠与唤醒

驱动程序使用`sleep()`和`wakeup()`等待设备：
- 进程调用`sleep()`等待输入或输出完成
- 中断处理程序调用`wakeup()`唤醒等待的进程

## 5.4 时钟中断

### 时钟中断的用途

时钟中断用于：
1. 抢占（preempt）正在运行的进程，切换到其他进程
2. 维护系统时间（`ticks`）
3. 唤醒调用`sleep(n)`的进程

### 时钟中断处理

1. RISC-V定时器定期触发中断
2. `timervec()`（kernel/kernelvec.S:32）处理时钟中断
3. `timervec()`调用`devintr()`
4. `devintr()`识别时钟中断，调用`yield()`
5. `yield()`放弃CPU，让调度器选择其他进程

### 时钟中断与进程切换

时钟中断发生在用户空间或内核空间：
- **用户空间**：安全的，可以立即切换进程
- **内核空间**：不安全，不能立即切换，只设置标志
- 当从内核空间返回用户空间时，检查标志，如果设置了则切换进程

### 原子操作

时钟中断处理使用原子操作（`amoswap.w.aq`）来安全地与内核通信：
- 避免竞争条件
- 确保标志的读写是原子的

## 5.5 现实世界

- 真实系统有许多不同类型的设备（磁盘、网络、显卡、USB等）
- 驱动程序代码通常占内核代码的大部分
- 现代设备更复杂（如PCIe、NVMe、千兆以太网）
- DMA（直接内存访问）：设备可以直接读写RAM，无需CPU参与
- MSI（消息信号中断）：设备写入特定内存地址触发中断
- 中断控制器（如APIC）可以将中断路由到特定CPU
- 现实中的驱动程序通常更复杂，支持：
  - 多种设备型号
  - 热插拔
  - 电源管理
  - 性能优化
  - 错误处理和恢复
